INTELLIGENCE WITH A PURPOSE

Assistance that earns
its place in the workflow.

Every suggestion has a boundary. Inventory facts, ownership and publication remain backend responsibilities.

01

Describe the journey.

The concierge turns supported trip language into catalog constraints and returns up to three eligible offers, with stored prices and match explanations.

No-key interpretation works. A live external-provider call remains unverified.
02

See why a car fits.

Explicit preferences combine hard constraints with documented category and occasion weights. Rankings use actual offer facts.

Transparent rules, with no invented confidence percentages.
03

Start with rough notes.

The supplier assistant suggests editable details and completeness warnings. Preview, apply, save and submit remain separate actions.

Suggestions cannot publish a vehicle or invent specifications.
04

Read the activity honestly.

Scoped summaries use recorded listing states, inquiries, categories and detail API requests.

Descriptive aggregates, including repeated/demo calls—not demand predictions.
05

Review the photography.

Local checks flag basic resolution, darkness and edge-detail issues, identify identical normalized uploads, and explain a cover score.

Image heuristics do not establish vehicle identity, ownership or specifications.

ONE AUTHORITY

FastAPI + PostgreSQL

Normalized memberships, service areas, multiple categories and ordered images. Shared eligibility protects discovery, recommendations and inquiries.

CONTROLLED PUBLICATION

Approval is enforced.

Suppliers cannot publish their own offers. Suspension removes visibility; material edits require renewed review. Inquiry and outbox records commit together.

RESPECT THE EXISTING PLATFORM

WordPress keeps its role.

A thin API bridge was tested in local WordPress for catalog rendering and suspension/restoration. Production routing and SEO rollout remain staging work.

What this review page is

A hosted presentation of a locally tested prototype and its source. The full marketplace is not deployed here. There is no checkout or confirmed reservation. Remote CI has a startup failure before jobs; operational hardening and live model verification remain documented work.
